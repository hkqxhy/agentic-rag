# Phase 2 容量与效果基线

本文记录秋招演示环境的可复现基线。测试环境为阿里云杭州地域 4 核 8 GiB ECS，应用通过 Docker Compose 部署，模型使用阿里云百炼 `qwen-plus`，API 与 Worker 通过 Redis 队列解耦。

## 真实模型小样本门禁

| 指标 | 2 并发 / 4 次问答 | 5 并发 / 5 次问答 |
| --- | ---: | ---: |
| 模型生成成功率 | 100% | 100% |
| grounded 率 | 100% | 100% |
| HTTP 失败率 | 0% | 0% |
| 端到端平均延迟 | 6.12 s | 11.61 s |
| 端到端 P95 | 8.04 s | 17.27 s |
| 端到端最大延迟 | 8.51 s | 17.89 s |
| 安全过滤触发率 | 100% | 80% |

5 并发时共完成 75 次 HTTP 请求，全部成功。HTTP P95 为 1.23 s，明显低于 17.27 s 的问答端到端 P95，说明当前主要等待来自单 Worker 排队和云端模型生成，而不是 Web、API、PostgreSQL 或 Redis 基础链路。

该结果支持“约 100 个注册用户、峰值约 5 个同时进行模型问答”的初版容量定位。它不能外推为 100 个用户同时调用大模型；模型并发提高前应先评估百炼配额、Worker 数量和预算。

## 100 用户平台层门禁

平台门禁不会发送聊天消息，因此不会调用千问。每个虚拟用户完成一次注册、首页访问、健康检查、会话恢复、会话列表、创建、详情、重命名和软删除，用于隔离验证 Caddy、Next.js、FastAPI、PostgreSQL、Redis 限流及会话体系。

```bash
sudo VUS=100 ITERATIONS=1 \
  bash deploy/ecs/verify-phase2-platform-load.sh
```

默认门禁：失败率低于 1%，检查通过率高于 99%，认证 P95 低于 20 s，读取 P95 低于 3 s，写入 P95 低于 5 s，完整用户旅程 P95 低于 30 s。该测试会创建 100 个隔离测试账号和对应审计记录，但不会产生模型费用。

## 对外表述边界

- 可以说明 5 并发真实模型链路 100% 成功、P95 17.27 s。
- 100 用户平台测试通过后，可以说明平台层完成 100 虚拟用户突发验证。
- 不应表述为“100 个大模型请求并发”，除非后续单独完成该档测试。
- 当前数据属于小样本工程门禁，不替代长时间稳定性、故障注入和正式学校知识库效果评测。
