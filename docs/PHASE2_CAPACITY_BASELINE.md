# Phase 2 容量与效果基线

本文记录预生产演示环境的可复现基线。测试环境为阿里云杭州地域 4 核 8 GiB ECS，应用通过 Docker Compose 部署，模型使用阿里云百炼 `qwen-plus`，API 与 Worker 通过 Redis 队列解耦。

## 真实模型小样本门禁

| 指标 | 2 并发 / 4 次问答 | 5 并发 / 5 次问答 |
| --- | ---: | ---: |
| 模型生成成功率 | 100% | 100% |
| grounded 率 | 100% | 100% |
| HTTP 失败率 | 0% | 0% |
| 端到端平均延迟 | 6.12 s | 11.61 s |
| 端到端 P95 | 8.04 s | 17.27 s |
| 端到端最大延迟 | 8.51 s | 17.89 s |
| 安全过滤触发率 | 100% | 80% |

5 并发时共完成 75 次 HTTP 请求，全部成功。HTTP P95 为 1.23 s，明显低于 17.27 s 的问答端到端 P95，说明当前主要等待来自单 Worker 排队和云端模型生成，而不是 Web、API、PostgreSQL 或 Redis 基础链路。

该结果支持“约 100 个注册用户、峰值约 5 个同时进行模型问答”的初版容量定位。它不能外推为 100 个用户同时调用大模型；模型并发提高前应先评估百炼配额、Worker 数量和预算。

## 平台层目标门禁与突发上限

平台测试不会发送聊天消息，因此不会调用千问。每个虚拟用户完成一次注册、首页访问、健康检查、会话恢复、会话列表、创建、详情、重命名和软删除，用于隔离验证 Caddy、Next.js、FastAPI、PostgreSQL、Redis 限流及会话体系。

正式门禁对应首版“峰值 10 至 20 人在线”的容量目标：

```bash
sudo VUS=20 ITERATIONS=1 \
  bash deploy/ecs/verify-phase2-platform-load.sh
```

100 用户同时首次注册属于超出目标负载的突发压力测试：

```bash
sudo VUS=100 ITERATIONS=1 \
  bash deploy/ecs/verify-phase2-platform-load.sh
```

默认门禁：失败率低于 1%，检查通过率高于 99%，认证 P95 低于 20 s，读取 P95 低于 3 s，写入 P95 低于 5 s，完整用户旅程 P95 低于 30 s。

### 20 用户正式门禁实测

| 指标 | 结果 | 门禁 |
| --- | ---: | ---: |
| 检查通过率 | 100%，180/180 | > 99%，通过 |
| HTTP 失败率 | 0%，0/180 | < 1%，通过 |
| 吞吐量 | 29.53 req/s | 记录项 |
| 认证 P95 | 4.30 s | < 20 s，通过 |
| 读取 P95 | 0.93 s | < 3 s，通过 |
| 写入 P95 | 0.32 s | < 5 s，通过 |
| 完整旅程 P95 | 6.07 s | < 30 s，通过 |

20 个并发用户全部完成注册、首页访问、登录态恢复和会话全生命周期，所有功能、可靠性与延迟门禁均通过。该结果关闭首版平台容量门禁，并支持“约 100 个注册用户、峰值 10 至 20 人在线”的目标容量表述。

### 100 用户突发实测

| 指标 | 结果 | 门禁 |
| --- | ---: | ---: |
| 检查通过率 | 100%，900/900 | > 99%，通过 |
| HTTP 失败率 | 0%，0/900 | < 1%，通过 |
| 吞吐量 | 32.78 req/s | 记录项 |
| 认证 P95 | 20.61 s | < 20 s，未通过 |
| 读取 P95 | 6.37 s | < 3 s，未通过 |
| 写入 P95 | 2.06 s | < 5 s，通过 |
| 完整旅程 P95 | 27.32 s | < 30 s，通过 |

100 个用户均完成完整旅程且没有请求失败，证明系统在该突发下保持数据与功能正确性；但认证和读取延迟门禁未通过。该测试让 100 个账户同时执行 Argon2 密码哈希，已明显超过“100 个注册用户、10 至 20 人峰值在线”的实际容量目标。4 核 CPU 饱和期间读取请求也被拖慢，因此该结果应记录为压力上限，不能表述为 100 并发完全通过。

## 对外表述边界

- 可以说明 5 并发真实模型链路 100% 成功、P95 17.27 s。
- 可以说明 20 并发完整平台旅程 180 次请求零失败、旅程 P95 6.07 s，正式容量门禁全部通过。
- 可以说明 100 虚拟用户突发下 900 次请求零失败、完整旅程 P95 27.32 s，同时明确认证和读取延迟门禁未通过。
- 不应表述为“100 个大模型请求并发”，除非后续单独完成该档测试。
- 当前数据属于小样本工程门禁，不替代长时间稳定性、故障注入和正式学校知识库效果评测。
