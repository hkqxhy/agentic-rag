# PAIMON Next 创新点与工程落地说明

## 场景聚焦

新版 PAIMON 聚焦“新生问答”这一垂直场景，不再把系统定位成泛用聊天机器人。新生问题通常具有三个特点：

1. 高流程性：报到、身份认证、校园卡、医保、选课、体检等问题需要步骤化回答。
2. 高时效风险：时间、费用、入口链接和年级安排容易过期。
3. 高信任要求：错误回答会影响真实办事流程，需要明确来源和置信度。

## 技术创新点

### 1. 无模型可用的 RAG 基线

旧版强依赖本机 Qwen 服务、ModelScope embedding 路径、LangChain、FAISS 和 Flask。新版核心只使用 Python 标准库，即使没有大模型和向量库，也能完成：

- 多格式知识加载
- 混合检索
- 来源引用
- 抽取式回答
- HTTP API
- CLI 验证

这让系统可以先稳定上线，再逐步接入更强模型。

### 2. 混合检索与 RRF 融合

新版采用 BM25 + 字符 ngram 检索，并使用 Reciprocal Rank Fusion 融合两个排序结果。对中文新生问答来说，这种方案能同时覆盖：

- 精确词命中，如“校园卡”“统一身份认证”
- 问法变化，如“密码忘了”“登录不上”
- 短问题和口语化追问

### 3. 面向新生领域的轻量重排

重排阶段不只看文本相似度，还会结合：

- 查询词覆盖率
- 标题/原问题匹配
- QA 结构化来源加权
- 新生高频场景词加权

这比单纯相似度排序更符合垂直问答场景。

### 4. 检索质量自检

当最高分或排序间隔不足时，系统会主动承认资料不足，并根据意图提示用户补充关键信息，例如校区、年级、书院、系统名称或具体流程。这是面向真实办事问答的保守策略。

### 5. 强引用与过期资料提醒

回答会返回 `sources/reference`，并用 `[S1]` 等编号标注来源。系统还会检测历史年份、级别、日期、费用和链接，提醒以当前年度官方通知为准。

### 6. 可选生成增强

配置 `PAIMON_LLM_BASE_URL` 后，系统会调用 OpenAI-compatible 本地服务进行生成式 RAG。未配置或服务异常时自动降级，不影响基本问答能力。

## 工程落地考量

- 保留旧入口：`PAIMON().rag()` 和 `/RAG/chat` 仍可用。
- 标准库 HTTP API：减少部署环境依赖。
- 本地缓存索引：启动时自动复用 `.paimon_index/index.json`。
- 可测试：`tests/` 覆盖解析、检索和无 LLM 回答。
- 可扩展：后续可以把 dense embedding、cross-encoder reranker、FastAPI、权限控制和管理后台接入现有模块边界。

## 后续可扩展方向

1. 接入正式向量模型和 cross-encoder 重排，提高语义召回与排序质量。
2. 增加定时爬取/人工审核后台，把学校官方通知变成可追溯知识源。
3. 增加答案评测集，覆盖身份认证、报到、医保、选课、宿舍等高频场景。
4. 接入 QQ/微信/网页前端，复用同一个 `/ask` API。
5. 增加权限和敏感信息保护，避免收集身份证号、手机号等个人隐私。
